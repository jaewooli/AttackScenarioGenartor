# 참조 문서 대조 요약 (M0.5 + WBS 1.6)

> 질문은 하나다: **"이 인프라 상태(보안 조치, 공격 조건, 설정)를 IR로 표현할 수 있는가?"**
> 내 머리로 만든 목록이 아니라 공인된 목록과 대조해서 IR의 빈틈을 찾는다.
> 각 대조표는 원본(YAML)에서 생성되고, 테스트가 "표현 불가 0"과 문서 최신 여부를 확인한다.

## 대조표만으로는 안 보이고 샘플에 써봐야 보인 것

샘플 `docs/samples/shop-hybrid.ir.yaml`에 **설정 키 65개 전부**와 새 요소를 실제로 써서 검증을 통과시켰다. 이 과정에서 대조표가 "표현 가능"이라고 했던 것 중 3개가 사실은 표현할 수 없었다.

1. 저장소가 어느 서버 위에 있는지 표현 불가 → `hosts` 확장 (M0.5)
2. YAML이 `on`/`off`를 참/거짓으로 읽음 → 허용값 변경 (M0.5)
3. CIS 4.10 단말 잠금: 대조표는 `auth.lockout`으로 표현 가능이라 했지만 그 키를 단말에 붙일 수 없었음 → `applies_to` 확장 (1.6.4 중 발견)

교훈: **대조표의 "표현 가능"은 실제 IR에 써봐야 확정된다.** 그래서 테스트가 "사전의 모든 키가 샘플에서 한 번 이상 쓰였는가"를 확인한다.

## 반복해서 나온 한계 (의도적으로 보류)

| 한계 | 나온 곳 | 결정 |
|---|---|---|
| 시스템 간 **데이터 흐름** 엣지가 없음 | CIS 3.8, D3FEND D3-DEM, ISMS-P 3.3 | P2 규칙 설계 때 유출 경로 판단에 필요한지 보고 결정 |
| **애플리케이션 내부**(입력 검증, 객체 단위 권한, 예외 처리)는 묶음 키 하나 | ASVS, Top 10 | 의도된 한계 (L3, MVP 범위 밖) |
| **탐지·시간**이 모델에 없음 | 완화책 일부, CIS 8·13장, D3FEND Detect, CSF DE | 단조성 가정의 결과. 시간·탐지 모델은 ROADMAP "나중에" |
| **방어 무력화 상태**를 공격자 상태로 표현 못 함 | ATT&CK 방어 무력화 전술 | IR이 아니라 공격자 상태 모델의 빈틈. P2에서 결정 |
| 파일 단위 권한, 인증서 템플릿 단위 | M1022, D3-LFP, T1649, k8s 5.1.11 | 노드 단위로 근사. 필요하면 P2에서 노드 타입 추가 |

## 확보하지 못한 원문 (다음에 받으면 같은 방식으로 추가)

- **KISA 주요정보통신기반시설 기술적 취약점 분석·평가 가이드**: 공식 PDF 링크를 자동으로 받지 못함
- **ISMS-P 인증기준 원문**: 영역 구성은 알려진 구조를 따름. 원문 대조 필요
- **CIS Benchmarks 원문**: 내려받기에 등록 필요 (쿠버네티스는 kube-bench로 대체)
- **DISA Windows STIG**: 사이트에서 자동 내려받기 불가

## 라이선스 처리

- **CIS Controls / CIS Benchmarks**: CC BY-NC-ND 4.0 및 이용 약관(원문 게시·2차 저작 제한) → 번호와 자체 작성 요약만 저장. 원문은 저장소에 넣지 않음 (테스트가 확인)
- **AWS 기준**: 번호와 자체 요약만
- **MITRE ATT&CK, D3FEND**: ID·이름·분류만 저장 (설명문 제외)
- **DISA STIG**: 미국 정부 공개 자료. 그래도 일관성을 위해 번호와 자체 요약만
