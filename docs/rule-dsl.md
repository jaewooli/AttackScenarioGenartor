# WBS 2.2 규칙 DSL 명세 v1

규칙 하나는 검증된 IR에서 한 결론을 평가한다. 아래 YAML은 v1 문법이다. 현재 Python 프로토타입은 규칙을 코드로 평가한다.

```yaml
id: R10
version: 1
when:
  all:
    - relation: {type: reaches, from: "$external", to: "$group"}
    - relation: {type: runs, from: "$host", to: "$service"}
    - check: {name: group_membership, args: ["$host", "$group"]}
    - check: {name: service_endpoint_matches, args: ["$service", "$external", "$group"]}
then: {kind: candidate, subject: "$service", question: "경유 장비가 이 서비스로 전달하는가?"}
attack_ids: []
prior: null
```

## 규칙과 평가 기록

- id와 version이 규칙을 식별한다. 달러 기호로 시작하는 변수는 패턴에서 바인딩한다. 같은 변수는 같은 IR 객체를 가리킨다. 출력과 검사에서 참조하는 변수는 앞선 패턴에서 바인딩해야 한다.
- all은 같은 바인딩에서 모든 조건을 요구한다. relation은 관계 유형과 방향을 일치시키고, check는 이름이 등록된 판정만 호출한다. 전제가 명시적으로 거짓이면 해당 바인딩에서 결론을 생성하지 않는다.
- attack_ids는 검토된 ATT&CK 기법 참조 목록이다. prior는 단계 성공에 대한 사전분포 참조다. null이면 수치 평가를 보류한다. IR의 confidence는 입력 근거에 대한 확신도다.
- 각 결과에 규칙 ID와 버전, 입력 버전, 프로필, 바인딩, 전제 사실과 IR 근거를 기록한다. 같은 결론의 독립적인 도출 근거는 각각 보존한다. 출력은 결론과 근거 식별자 순으로 정렬한다.

| 결과 | 판정 기준 | 필수 기록 |
|---|---|---|
| 확정 사실 | 결론에 필요한 전제가 모두 확인되고 규칙의 효과가 결정적 | 결론과 전체 근거 |
| 평가 후보 | 관측된 조건이 있으며 규칙에 명시된 추가 확인으로 결론을 판정할 수 있음 | 관측 근거와 확인 질문 |
| 미평가 | 필요한 정책 의미나 검사 연산을 지원하지 않음 | 해당 필드와 보류 이유 |

후속 결정론적 규칙의 전제로는 확정 사실만 사용한다. 조건부 권한의 조건 해석이나 상속된 거부의 우선순위가 미정이면 권한 판정을 보류한다. 도달성 검사에서는 포트, 프로토콜, 경유 조건을 근거에 포함한다.

## shop-hybrid 판정 예시

| 샘플 근거 | 평가할 결론 | 기대 결과 |
|---|---|---|
| hosts(db-01, store-db) | 구성에 선언된 저장소 배치 | 확정 사실. 이 관계를 입력 근거로 보존 |
| ext-internet에서 group:nsg-web로 TCP 443 허용, via가 lb-01 | svc-web 외부 노출 | 평가 후보. 서비스 포트·그룹이 일치해도 lb-01의 전달 설정 확인 필요 |
| role-backup이 store-backup에 write 권한 보유 | 저장된 각 데이터의 수정 가능 여부 | 미평가. 저장소 쓰기 권한이 개별 데이터에 미치는 의미 미정 |

세 예시는 프로토타입의 `assessments` 출력과 통합 테스트에서 확인한다. 구성 관계와 저장소 권한의 해석 범위는 입력 전체에서 평가하고, 외부 노출 후보는 프로필별로 평가한다. 각 기록의 evidence는 입력 관계의 식별자다. `rule`과 `rule_version`은 적용한 판정 정의를 식별한다. `input_revision`은 파싱한 IR을 키 정렬·공백 없는 UTF-8 JSON으로 직렬화한 SHA-256이다. 배열 순서는 보존한다. `profile_ids`는 해당 실행에 투입한 프로필 ID의 정렬 목록이다. 구성 자체의 판정과 수동 시드만 사용한 실행에서는 빈 목록을 반환한다.

## v1 작성 규약

규칙의 필수 키는 위 예시의 여섯 키다. id는 비어 있지 않은 문자열, version은 양의 정수다. 같은 규칙 집합에서 (id, version) 조합은 유일하다. 전제나 효과의 의미가 달라지면 버전을 올린다.

| 요소 | 형식과 의미 |
|---|---|
| when.all | 하나 이상의 패턴 목록. relation, check 또는 fact를 순서대로 평가한다. fact는 kind와 순서 있는 args로 기존 상태 사실에 일치시킨다. |
| then.kind = fact | fact 필드에 상태 모델의 kind와 args를 둔다. 전제가 성립하면 구체화한 사실을 집합에 추가한다. 기존 사실도 새 도출 근거를 보존한다. |
| then.kind = candidate | subject와 question을 기록한다. 후보는 사실 집합 밖에 보존한다. |
| then.kind = unevaluated | subject와 reason을 기록한다. 지원하지 않는 입력 조건은 평가 시에도 이 결과를 낼 수 있다. |
| attack_ids | 저장소의 ATT&CK 참조 버전에서 확인한 기법 ID 문자열 목록. 중복은 오류이며 관련 기법을 지정하지 않은 경우 빈 목록이다. |
| prior | null 또는 id와 version을 가진 참조 객체. 참조 대상은 적용 조건, 분포 종류·모수, 출처를 제공한다. 참조 해석에 실패하면 확률 계산을 보류하고 그 사유를 기록한다. |

알 수 없는 규칙 키, 정의되지 않은 변수, 잘못된 사실 인자 수는 규칙 정의 오류로 처리한다. 입력에 관계나 값이 누락된 경우에는 그 부재만으로 부정 사실을 도출할 수 없다. 확률적 효과는 후보로 보존한다. 동일 사건을 가리키는 여러 근거의 확률 결합과 분포 보정은 각각 P3와 P4에서 다룬다.

상태 효과의 표기 예로 이미 알려진 대상에 대한 사실은 `then: {kind: fact, fact: {kind: knows, args: ["$subject"]}}`로 표현한다. subject는 선행 패턴이 바인딩해야 한다. WBS 2.3에서 이 규약으로 초기 규칙을 작성한다.
